## 一、已上线且验证通过

两个线上 bug 修完了，都在 `main` 分支、Railway 已部署。

### 1. 时区错误

**症状**：北京时间 11:07 显示 "Good afternoon"，日期不切换到今天。

**根因**：Railway 容器时区是 UTC，比北京慢 8 小时。所有时间计算跑在服务端，
用的是服务器时钟。**数据库存的时间戳一直是对的**（UTC 标准、带时区），
只是渲染时用错了钟。

**修复**：Railway 环境变量加 `TZ=Asia/Shanghai`。

- `Asia/Shanghai` 就是北京时间（UTC+8）。IANA 时区库用区内人口最多的城市命名，
  没有 `Asia/Beijing` 这个标识符，写了会被忽略、回退 UTC。
- 健康检查 API 加了 `timezone` 字段（`tz` / `localTime` / `offsetHours`），
  以后排查时区问题直接看这里。

**验证**：云端 14:41 显示 `Good afternoon` + `September 16`，正确。

### 2. 图片每次部署就全丢

**症状**：每次改代码 push 后，所有图片 404。

**根因（两层）**：

第一层 —— 容器文件系统是临时的（ephemeral）。图片存在容器磁盘里，
每次部署换新容器，磁盘一起销毁。数据库 media 记录还在，但文件没了。

第二层 —— 配好 Backblaze B2 后上传仍然失败。因为 **AWS SDK ≥3.729
默认给每个上传请求加 `x-amz-checksum-crc32` 头，而 B2 不认这个头**，
直接返回 "Unsupported header"。本项目装的是 3.1131.0，受影响。

**修复**：

- `src/lib/storage.ts` 从硬编码 R2 endpoint 改为读通用 `S3_*` 变量，
  任何 S3 兼容服务都能用（B2 / R2 / 阿里云 OSS / 七牛云）。
  保留 `R2_*` 作为回退，不影响已有部署。
- S3Client 设 `requestChecksumCalculation: "WHEN_REQUIRED"`（关键，见上）
- 生产环境用本地存储时打印醒目警告 —— 这个坑踩过一次，别再静默丢文件
- 健康检查 `storage` 字段改为 `cloud` / `local`，部署后应确认是 `cloud`

**Railway 环境变量**：

```
TZ                   = Asia/Shanghai
S3_ENDPOINT          = https://s3.us-east-005.backblazeb2.com
S3_REGION            = us-east-005
S3_BUCKET_NAME       = digitalself
S3_ACCESS_KEY_ID     = (B2 Application Key 的 keyID)
S3_SECRET_ACCESS_KEY = (B2 Application Key 的 applicationKey)
```

**验证**：`/api/health?probe=storage`（需登录）实测写入/读回/删除全部成功。

## 二、性能分析结论：瓶颈不在数据库

实测生产环境延迟构成：

| 测量对象 | 首字节 | 说明 |
|---|---|---|
| TCP + TLS 握手 | 0.42–0.47s | 纯网络，代码无关 |
| favicon.ico（零渲染） | **0.74s** | 这条链路的地板价 |
| /api/health（1 次查询） | 0.61–0.81s | 与静态文件持平 |
| /moments | 0.94–0.99s | 减去地板价 → 渲染仅约 0.2s |
| 冷启动 | 2.6–2.8s | 容器/连接池初始化 |

**一个静态图标都要 0.74s**，说明固定成本就是 0.7s（Railway 部署在美国区，
用户在国内）。页面 0.95s 里真正花在查库和渲染上的只有 200ms。

**所以：加 Redis、优化 SQL 都没用** —— 最多省那 200ms 里的一部分，
动不了 0.7s 的地板。迟钝感的真正来源是这 1 秒里屏幕完全没反馈。

想真正降低网络延迟只能换部署区域（Railway 支持选 Singapore / Tokyo），
但那涉及重建服务和数据库迁移，风险较高，建议和「Railway 费用」一起决策。

## 七、踩过的坑（写下来免得再犯）

### `.env` 里的 bcrypt 哈希必须用反斜杠转义

```bash
# ✅ 正确（本地 .env.local）
AUTH_PASSWORD_HASH=\$2b\$10\$d26QjuBF...

# ❌ 单引号不管用 —— dotenv 仍会展开 $，读进来只有 35 字符
AUTH_PASSWORD_HASH='$2b$10$d26QjuBF...'

# ❌ 裸写同样被截断
AUTH_PASSWORD_HASH=$2b$10$d26QjuBF...
```

`$2b` / `$10` / `$d26...` 会被当成变量名展开成空字符串。
正确的 bcrypt 哈希是 **60 字符**，可以这样检查：

```bash
node -e "const{loadEnvConfig}=require('@next/env');loadEnvConfig(process.cwd(),true);console.log(process.env.AUTH_PASSWORD_HASH?.length)"
```

**Railway 环境变量则相反** —— 直接写 `$2b$10$...`，不要转义。

### 文件夹改名会让会话工作目录失效

本项目原名 `ranlee_副本`，2026-09-16 改为 `ranlee`。
会话的 cwd 还钉在旧路径，导致命令跑到不存在的目录。
命令要显式 `cd /Users/ranli/Desktop/ranlee && ...`。

### `/api/health` 是公开路由

存储自检 `?probe=storage` 会真写文件，所以加了登录校验 ——
不设门槛的话任何人都能反复往你的存储桶里写东西。

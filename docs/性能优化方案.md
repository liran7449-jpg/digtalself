# 性能优化方案 - /me 页面

## 问题诊断

### 现状
- **TTFB (Time to First Byte)**: 5.7秒（目标: <1秒）
- **LCP (Largest Contentful Paint)**: 6.3秒（目标: <2.5秒）
- **目标切换延迟**: 2秒（目标: <300ms）

### 根本原因

#### 1. N+1 查询问题（🔴 严重）
**位置**: `src/services/goal-link-service.ts:135-147`

```typescript
// 当前实现：对每个 moment 单独查询 media
const result = await Promise.all(
  rows.map(async (row) => {
    const mediaRecords = await db
      .select({ id: media.id })
      .from(momentMedia)
      .innerJoin(media, eq(momentMedia.mediaId, media.id))
      .where(eq(momentMedia.momentId, row.id));
    // ...
  })
);
```

**影响**:
- 10 个 evidence = 11 次数据库查询（1次主查询 + 10次子查询）
- Railway 数据库在美国西部，每次查询 RTT ~200-600ms
- **总延迟**: 10 × 200ms = 2000ms

#### 2. 服务端渲染阻塞（🔴 严重）
**位置**: `src/app/me/page.tsx:27-46`

整个页面等待所有数据查询完成才返回：
- goals 列表
- counts（每个 goal 的 evidence 数量）
- evidence（包含 N+1 查询）
- 每个 moment 的 media

#### 3. 客户端导航慢（🟡 中等）
**位置**: `src/app/me/MeContent.tsx`

切换目标时整页 SSR 重新加载，而不是只获取新 evidence。

#### 4. 地理延迟（🟡 中等）
- Railway 数据库在美国
- 从中国访问 RTT 高

## 优化方案

### Phase 1: 立即优化（预期减少 3-5秒）

#### ✅ 1.1 修复 N+1 查询
**优先级**: P0  
**预期收益**: 减少 2-5秒

将多次查询合并为一次 LEFT JOIN：

```typescript
async listEvidence(userId: string, goalId: string): Promise<GoalEvidence[]> {
  const rows = await db
    .select({
      momentId: moments.id,
      content: moments.content,
      date: moments.date,
      occurredAt: moments.occurredAt,
      mediaId: media.id,
    })
    .from(momentGoals)
    .innerJoin(goals, eq(momentGoals.goalId, goals.id))
    .innerJoin(moments, eq(momentGoals.momentId, moments.id))
    .leftJoin(momentMedia, eq(moments.id, momentMedia.momentId))
    .leftJoin(media, eq(momentMedia.mediaId, media.id))
    .where(...)
    .orderBy(desc(moments.occurredAt));

  // 在内存中聚合（按 momentId 分组）
  const grouped = new Map<string, GoalEvidence>();
  for (const row of rows) {
    const key = row.momentId;
    if (!grouped.has(key)) {
      grouped.set(key, {
        id: row.momentId,
        content: row.content,
        date: row.date,
        occurredAt: row.occurredAt,
        mediaPaths: [],
      });
    }
    if (row.mediaId) {
      grouped.get(key)!.mediaPaths.push(row.mediaId);
    }
  }
  return Array.from(grouped.values());
}
```

**验证方法**: 
- 查看 Railway 日志，确认查询次数减少
- 测量 `/me` 页面加载时间

### Phase 2: 中期优化（1-2周内）

#### 2.1 添加数据库索引
**优先级**: P1  
**预期收益**: 减少 100-300ms

```sql
CREATE INDEX idx_moment_goals_goal_id ON moment_goals(goal_id);
CREATE INDEX idx_moment_goals_moment_id ON moment_goals(moment_id);
CREATE INDEX idx_moment_media_moment_id ON moment_media(moment_id);
CREATE INDEX idx_moments_user_occurred ON moments(user_id, occurred_at DESC);
```

#### 2.2 使用 React Streaming + Suspense
**优先级**: P1  
**预期收益**: 首屏渲染提前 1-2秒

```tsx
<Suspense fallback={<GoalsSkeleton />}>
  <GoalsList />
</Suspense>
<Suspense fallback={<EvidenceSkeleton />}>
  <EvidenceList goalId={selectedId} />
</Suspense>
```

#### 2.3 数据缓存策略
**优先级**: P1  
**预期收益**: 重复访问减少 2-4秒

- Goals 列表：缓存 5 分钟（很少变）
- Evidence：缓存 1 分钟
- Counts：缓存 5 分钟

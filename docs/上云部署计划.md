# Digital Self 上云部署计划

## 📋 目标

- 部署到云端，手机和电脑都能访问
- 简单密码保护，防止未授权访问
- 数据库迁移：SQLite → PostgreSQL
- 图片存储：本地文件 → Cloudflare R2
- 保持代码质量，做好版本管理

---

## 🏗️ 技术架构

### 当前架构（本地）
```
Next.js App (localhost:3000)
  ↓
SQLite 数据库 (data/digital-self.db)
  ↓
本地文件存储 (data/uploads/)
```

### 目标架构（云端）
```
Vercel (前端 + API)
  ↓
Railway PostgreSQL (数据库)
  ↓
Cloudflare R2 (图片存储)
```

## 🌳 分支管理策略

### 分支结构
```
main (稳定版本，已部署)
  ↓
develop (开发分支，集成测试)
  ↓
  ├─ feature/postgres-migration
  ├─ feature/r2-storage
  ├─ feature/simple-auth
  └─ feature/env-config
```

### 工作流程
1. **开发新功能**：从 `main` 创建 `feature/*` 分支
2. **本地测试**：确保功能完整可用
3. **合并到 main**：测试通过后合并
4. **部署**：main 分支自动部署到 Vercel

### 发布流程
```bash
# 1. 开发功能
git checkout -b feature/postgres-migration
# ... 开发 + 测试 ...
git commit -m "feat: 添加 PostgreSQL 支持"

# 2. 合并到 main
git checkout main
git merge feature/postgres-migration

# 3. 打标签
git tag v0.9.0-cloud-ready
git push origin main --tags

# 4. 自动部署（Vercel）
```

## 🔐 安全配置

### 简单密码认证

**登录流程：**
```
访问任意页面 → 检测未登录 → 跳转 /login
输入密码 → 验证通过 → 设置 Session Cookie → 进入应用
```

**密码存储：**
```
环境变量：AUTH_PASSWORD_HASH（bcrypt 加密）
不存储在代码里，只在 Vercel 配置
```

**Session 管理：**
```
Cookie: session_token (HttpOnly, Secure, SameSite=Lax)
有效期: 30 天
```

### 环境变量（生产环境）
```bash
# 数据库
DATABASE_URL=postgresql://user:pass@host:5432/dbname

# 对象存储
R2_ACCOUNT_ID=xxx
R2_ACCESS_KEY_ID=xxx
R2_SECRET_ACCESS_KEY=xxx
R2_BUCKET_NAME=digital-self

# 认证
AUTH_PASSWORD_HASH=$2a$10$... (bcrypt hash)
SESSION_SECRET=random-secret-key-32-chars

# Next.js
NEXT_PUBLIC_APP_URL=https://your-app.vercel.app
```

## 📦 数据迁移方案

### 方案 A：自动脚本（推荐）
```bash
npm run migrate:to-cloud
```

**流程：**
1. 读取本地 SQLite 数据
2. 转换格式
3. 批量插入 PostgreSQL
4. 上传图片到 R2
5. 验证数据完整性

**时间：** 5-10 分钟（取决于数据量）

### 方案 B：手动导出/导入
```bash
# 1. 导出 SQLite 数据
npm run export:data

# 2. 上传到云端数据库
psql $DATABASE_URL < export.sql

# 3. 手动上传图片到 R2
```

## ⚠️ 风险和应对

### 风险 1：数据库迁移失败
**应对：**
- 迁移前完整备份本地数据库
- 分批次迁移，逐步验证
- 保留本地版本作为回滚点

### 风险 2：图片上传失败
**应对：**
- R2 上传失败自动重试 3 次
- 本地保留原图副本
- 提供手动补传工具

### 风险 3：密码泄露
**应对：**
- 使用强密码（20+ 字符）
- 定期更换密码
- 后期升级到邮箱魔法链接

### 风险 4：部署后功能异常
**应对：**
- Vercel 支持一键回滚
- 保留 main 分支上一个稳定版本
- 灰度发布（先用测试域名）

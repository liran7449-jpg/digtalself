## 三、修掉的安全问题（4 个，都是真的）

### 1. `/api/debug-env` 把密码哈希挂在公网

`src/app/api/debug-env/route.ts` 无条件返回完整 `AUTH_PASSWORD_HASH`，
而且在 middleware 免认证白名单里。任何人 GET 一下就能拿去离线爆破。
**已删除。**

### 2. media 越权访问

`api/v1/media/[id]` 原来是「文件存在即可访问」，留着一行
`TODO: 多用户时检查 userId`。照片 id 是 ULID，会出现在页面 HTML、
浏览器历史里，拿到就能看别人的照片。**已修，越权返回 404。**

### 3. SESSION_SECRET 泄露（最严重）

`docs/TEST_REPORT.md:54` 写着生产在用的 session 密钥，已推到 GitHub。

**实测复现过**：不知道密码，只用那行文字封一个
`{userId:'me',isLoggedIn:true}` cookie，直接打开了线上 `/today`，
读到全部数据（HTTP 200）。

已换新密钥。换完再用旧 cookie 访问 → 307 跳登录页，确认失效。

### 4. 4 个脚本硬编码生产库连接串

`backup-cloud` / `verify-cloud` / `check-media` / `diagnose-time`
各自把含密码的连接串写在第一行，已推到 GitHub。
**已改为读 `CLOUD_DB_URL`**（`scripts/cloud-db.mjs` 统一入口）。

⚠️ 数据库密码本身还没换 —— 历史里那串仍是有效凭证。仓库私有所以
不紧急，但建议将来迁库时一起处理。Railway 没有直接的 rotate 功能。

### 防线

新增 `scripts/check-secrets.mjs`，扫 bcrypt 哈希 / 带密码的连接串 /
疑似真实 session secret / AWS 密钥。支持 `--staged` 提交前检查。

同类问题已发生三次，靠「记得别写进去」防不住。

## 四、测试隔离失效事件（我造成的）

本次会话开始时，我为了让测试跑起来执行了
`set -a; . ./.env.local; set +a; npx vitest run`，
把**真实本地库地址**注入测试进程，测试直接写进了开发库：

| 表 | 之前 | 之后 |
|---|---|---|
| moments | 66 | 85 |
| days | 44 | 68 |
| plan_items | 106 | 144 |

**为什么守卫没挡住**：`test-setup.ts` 的 `assertIsolated()` 检查的是
`DIGITAL_SELF_DB`（SQLite 时代变量），而代码 9 月已迁到 Postgres、
读的是 `DATABASE_URL`。守卫全绿通过，同时连在真实库上。

**守卫查错变量比没有守卫更危险** —— 它给的是虚假的安全感。

已改为：测试库名必须以 `_test` 结尾，不满足直接拒绝执行。
已验证故意指向 `digitalself` 时测试会失败退出。

云端生产库全程未受影响。本地库已从云端重建。

## 六、生日彩蛋与账号菜单

### 彩蛋

`src/components/birthday/BirthdayGreeting.tsx`，只在生日当天的 Today 页出现。

不做弹窗 / 撒花 / 需要点「确定」的拦路屏 —— 那些是 SaaS 通知的做法，
会把「有人记得你的生日」变成一次系统事件。

**两个容易漏的点**：

1. 彩蛋必须在 Today 页的**两个 return 分支**都渲染。新用户首次登录时
   `day.status === "not_started"`，走的是 Morning Setup 那个提前返回 ——
   只加在主分支的话，「第一次登录」这个最该被祝福的时刻恰好看不到。

2. `isBirthdayToday` 用 `toDayKey()` 而不是 `new Date().getMonth()`。
   这个产品的「今天」以凌晨 4 点为界，18 日凌晨 2 点在产品语义里还是
   17 日。用自然日会出现「页面显示 17 日，却祝你 18 日生日快乐」。

**字段**：`users.birthday` 存 `"MM-DD"` 不含年份 —— 唯一用途是判断
「今天是不是生日」，年份用不上且能推算年龄（§6 不收集用不到的）。

格式归一在 `src/domain/birthday-plain.mjs`：`scripts/` 下是 .mjs、
没有 TS 编译步骤、import 不了 .ts。那边是唯一实现，`birthday.ts`
re-export。复制两份的话，改了正则只改一处就会出现
「脚本存进去了但彩蛋不显示」。

**`birthday_note`**（可选留言，替代默认祝福语）存在**收信人自己那一行**
上，不是去查写信人的数据 —— 后者需要跨用户查询，会破掉隔离边界。
这样彩蛋渲染只读当前用户自己的行，隔离规则不用开例外。

🎂 单独一个 `span` + 左边距：emoji 在 Playfair 里会回落到系统 emoji 字体，
跟着标题的 letter-spacing 走会和文字挤在一起。`aria-hidden` ——
读屏念「生日蛋糕」是噪音，前面那句话已经说完了。

### 账号菜单

`src/components/layout/AccountMenu.tsx`，取代原来孤零零的「退出」按钮。
显示当前用户名（多用户下「我现在是谁」要一眼可见），点开有
「修改密码」和「退出登录」。

**改密码入口不能放在登录页** —— 那个页面按定义是未登录状态，谁都能打开。
如果那里能改密码，任何人输入别人的用户名就能把对方锁在外面。
改密码必须先证明「你是你」，所以 API 也要求当前密码。

细节：点外部关闭用 `pointerdown` 而不是 `click`（click 在某些浏览器上
会先触发菜单项本身，导致刚点的那一下被当成「点了外面」）；Esc 关闭；
改密页加「先不改，回到 Today」（它不套 AppShell、没有导航栏，
误点进去就是死胡同）。

`AppShell` 改成 async server component，用 `getCurrentUserId` 而不是
`requireUserId` —— 外壳拿不到用户就不显示菜单，不该让整页崩掉。

## 八、常用命令

```bash
# 生产库连接串（Railway → Postgres → Connect → Public Network）
export PROD_DB="<DATABASE_PUBLIC_URL>"

# 看所有用户
DATABASE_URL="$PROD_DB" node scripts/user-admin.mjs list

# 开新账号（随机临时密码 + 强制改密，更安全）
DATABASE_URL="$PROD_DB" node scripts/user-admin.mjs create <用户名> '<显示名>' [生日MM-DD]

# 开新账号（指定密码，不强制改密）
DATABASE_URL="$PROD_DB" node scripts/user-admin.mjs create <用户名> '<显示名>' <生日> <密码> --keep-password

# 给已有账号补生日
DATABASE_URL="$PROD_DB" node scripts/user-admin.mjs set-birthday <用户名> 09-18

# 设生日彩蛋里那句话（替代默认的「很高兴你在这里。」），传空串则清掉
DATABASE_URL="$PROD_DB" node scripts/user-admin.mjs set-note <用户名> '<一句话>'

# 备份并验证可恢复（§30）
CLOUD_DB_URL="$PROD_DB" node scripts/backup-cloud.mjs
node scripts/verify-backup.mjs backups/cloud-backup-<日期>.json

# 凭据扫描
node scripts/check-secrets.mjs

# 上线新 migration（Railway 不会自动跑！先 migration 再部署）
DATABASE_URL="$PROD_DB" npx drizzle-kit migrate
```
